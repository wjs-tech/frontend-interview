## `this` 指向：四种绑定 + 箭头函数（⭐️⭐️⭐️）

**一句话结论：** `this` 不看函数在哪定义，只看**怎么被调用**——默认绑定（独立调用指向全局/undefined）、隐式绑定（谁点出来的指向谁）、显式绑定（call/apply/bind 指定）、new 绑定（指向新建的对象）；箭头函数没有自己的 this，直接沿用外层。

### 🍳 生活类比

`this` 就像聚餐时"**这桌谁买单**"——不是定座的时候定的，是**结账那一刻谁拍板**谁买单。函数定义时 this 是空的，调用那一刻才决定指向谁。

箭头函数则是那个"**永远不买单的人**"——它自己没有买单资格（没有自己的 this），只能看同桌（外层作用域）谁来买。

### 🔍 原理下沉

JS 里 this 是**运行时**绑定的，跟定义位置无关。四种绑定优先级从高到低：

1. **new 绑定**：`new Foo()`，this 指向刚创建的那个空对象；
2. **显式绑定**：`fn.call(obj)` / `apply` / `bind`，this 就是你塞进去的那个 obj；
3. **隐式绑定**：`obj.fn()`，this 是点号前面那个 obj；
4. **默认绑定**：以上都不是（独立调用 `fn()`），非严格模式指向 window，严格模式是 undefined。

箭头函数不参与这套规则——它压根没有 this，写的是外层的 this。所以它**不能当构造函数**（`new` 会报错），`call`/`bind` 也改不动它。

> 版本演进提醒：ES5 全靠那四种绑定，回调里 this 乱飞是家常便饭；ES6 箭头函数很大程度就是为治这个病——回调里想要外层的 this，用箭头函数就不用 `var self = this` 那种丑写法了。

### 🔁 对比学习（普通函数 vs 箭头函数）

```js
const obj = {
  name: '妍思',
  // 普通函数：this 看调用
  hi() {
    setTimeout(function () {
      console.log(this.name)  // undefined，this 丢了
    })
  },
  // 箭头函数：this 沿用外层
  hiArrow() {
    setTimeout(() => {
      console.log(this.name)  // '妍思'，稳
    })
  }
}
```

Vue 里的真实体感：Vue2 的 `methods` 里写 `setTimeout(function(){...})`，this 会变成 window，拿不到组件数据；换成箭头函数，this 还是组件实例。React 那边 class 组件要手动 `.bind(this)`，函数组件 + Hooks 干脆没有 this——等于换了个思路绕开这个问题。

核心差异一句话：**普通函数的 this 是"谁调用算谁的"，箭头函数是"生在哪算哪的"。**

### 💥 我踩过的坑

最经典的一次：把对象方法抽出来当回调传，`btn.onclick = obj.handle`，一点击 this 就丢了。当时还纳闷"方法明明挂在对象上，怎么 this 不对"。后来才记住——**只要脱离了 `obj.xxx()` 这个调用形式，隐式绑定就失效**。

还有 Vue2 里，`mounted` 中写 `setTimeout(function(){ this.fetch() })`，直接报 `this.fetch is not a function`。第一反应是生命周期不对，其实是普通函数把 this 换成了 window，改成箭头函数就好。这坑我踩过不止一次，现在看到回调里的普通函数会本能警惕。

### 🎯 面试官可能追问

- 箭头函数能当构造函数吗？为什么？（不能，没有 this 也没有 prototype，`new` 会报错）
- `bind` 返回的函数还能被 `call` 改 this 吗？（不能，bind 是硬绑定，一次定死）
- `call` / `apply` / `bind` 三者区别？（前两个立即调用、参数形式不同；bind 返回新函数不立即调）
- 手写一个 `call` / `bind` 的思路？（利用隐式绑定：把函数临时挂到目标对象上调用，用完删掉）

## 闭包：为什么会产生、内存视角、真实场景（⭐️⭐️⭐️）

**一句话结论：** 闭包 = 函数 + 它**记住的外层作用域**。内层函数被拿到外层执行完之后的地方用，依然能访问当初的变量——因为那些变量还被它"攥着"，没被垃圾回收。

### 🍳 生活类比

闭包像**搬家时随身带的便当盒**：函数从"出生的厨房"（外层作用域）离开时，把要用的食材（外层变量）打包带走了。哪怕原厨房都拆了（外层函数执行完），它到哪都能打开便当盒，用里面的东西。

### 🔍 原理下沉

JS 是**词法作用域**：函数能访问哪些变量，在它**定义那一刻**就定死了，跟在哪调用无关。内层函数只要引用了外层变量，这条引用链就一直留着——外层函数的执行栈销毁了，但被引用的变量还挂在内存里，因为内层函数哪天可能还要用。这就是闭包。

它常被误会成"内存泄漏"。其实不是：**该留的留着是闭包，不该留的留住了才叫泄漏**。你要是不小心让一个大对象一直被某个用不到的闭包攥着，那才是泄漏。

真实使用场景（我项目里真用过的）：
- **防抖 / 节流**：用闭包记住上次的定时器句柄；
- **保存私有状态**：不让外部直接改，只暴露几个操作方法；
- **柯里化**：`add(1)(2)`，一层层记住参数。

### 🔁 对比学习（var vs let 里的闭包）

```js
// var：循环共享同一个 i
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i))  // 3 3 3
}

// let：每次循环都是新的词法环境
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i))  // 0 1 2
}
```

顺带说 React：Hooks 里的"**陈旧闭包**"（stale closure）就是闭包的另一面——`useEffect` 里拿到的 state 是那次渲染的值，不是最新的。Vue 的响应式因为数据是同一个引用，回调里读到的一直是新的，就没这烦恼。这是我 Vue 转 React 时最不适应的一点。

核心差异一句话：**var 闭包是"大伙共用一个变量"，let 闭包是"每人发一份"。**

### 💥 我踩过的坑

for 循环 + var + setTimeout 打出一串 3，这个我面试真被问过，当场愣住。下来自己跑了一遍才彻底明白：setTimeout 的回调是循环全跑完才执行的，那时 i 已经是 3 了，而 var 又只有一份。换 let，或者干脆把 i 当参数传进去，就各是各的。

这块我坦白：原理能讲，但让我手写一个"不泄漏的闭包缓存"，我还是会多看两眼——没那么熟练。

### 🎯 面试官可能追问

- 闭包一定会内存泄漏吗？（不会，看引用是否还被需要；不需要了手动置 null 解除）
- 手写一个防抖函数，闭包在里面起什么作用？（记住 timer 句柄，新调用清掉旧的）
- 闭包和作用域链什么关系？（闭包能访问外层变量，靠的就是作用域链没断）

## 原型链与继承（⭐️⭐️）

**一句话结论：** 访问一个对象没有的属性，JS 会顺着 `__proto__` 一层层往上找，直到 `null` 为止——这条链就是原型链；`class` / `extends` 只是它的语法糖，底层还是原型。

### 🍳 生活类比

原型链像**在家里找东西**：先翻自己房间，没有就去问爸妈（父级原型），爸妈也没有就去问爷爷奶奶……一路问到最老的祖宗（`null`）。都说没有，那就是真没有（`undefined`），不存在"再问下去"。

### 🔍 原理下沉

几个关键关系，记住一张图就够：
- 每个**实例**有 `__proto__`，指向**构造函数的 `prototype`**；
- `Foo.prototype` 本身也是个对象，它的 `__proto__` 指向 `Object.prototype`；
- `Object.prototype.__proto__` 是 `null`，链到头。

`class` 和 `extends` 只是把这套 `__proto__` 链接包装得更像"正经继承"，底层没变。所以 `instanceof` 的原理就是：顺着左边实例的原型链找，看能不能碰到右边的 `prototype`。

> 版本演进提醒：ES5 继承要写 `Child.prototype = Object.create(Parent.prototype)` 再修 constructor，啰嗦易错；ES6 `class Child extends Parent` 一行搞定。但别被语法糖骗了——底层还是原型链。

### 🔁 对比学习（ES5 原型继承 vs ES6 class）

```js
// ES5：手动接原型链
function Parent(name) { this.name = name }
Parent.prototype.say = function () { console.log(this.name) }
function Child(name) { Parent.call(this, name) }
Child.prototype = Object.create(Parent.prototype)
Child.prototype.constructor = Child

// ES6：语法糖，底层一样
class Parent {
  constructor(name) { this.name = name }
  say() { console.log(this.name) }
}
class Child extends Parent {}
```

Vue2 里有个真实应用：`Vue.prototype.$bus = new Vue()` 挂全局事件总线——之所以每个组件都能 `this.$bus`，就是因为组件实例的原型链上挂着 `Vue.prototype`。理解了原型链，才懂这不是黑魔法。

核心差异一句话：**class 是"看起来更面向对象"的原型链，不是另一套继承。**

### 💥 我踩过的坑

早期我以为给实例逐个加方法就行，结果一百个实例就创建了一百份同样的方法，内存白瞎。后来才明白**共享的方法要挂到 prototype 上**，让所有实例顺着原型链共用一份。

还有个反直觉的：`Object.create(null)` 造出来的对象**没有原型**，连 `hasOwnProperty` 都没有。第一次见有人这么建"纯字典"对象时我还以为写错了，其实是故意掐断原型链防污染。

### 🎯 面试官可能追问

- `new` 一个构造函数时到底发生了什么？（建空对象 → 接原型链 → this 指向它执行 → 返回）
- `__proto__` 和 `prototype` 区别？（前者是对象指向原型的链；后者只有函数有，是"未来实例的原型"）
- 为什么方法要挂 `prototype` 而不是直接写进构造函数？（共享一份，省内存）

## 执行上下文、作用域、变量提升（⭐️⭐️⭐️）

**一句话结论：** JS 代码不是一行行裸跑的——运行前引擎会给每段代码先搭一个"运行环境"（执行上下文），把变量/函数声明提前登记进去（这就是提升），并定好"这个变量去哪找"（作用域和作用域链）。理解这三样，前面 `this`、闭包那些反直觉的现象就都有了根。

### 🍳 生活类比

**执行上下文**，像进公司接手项目时 HR 给你开的"临时工位"。工位上强制摆三样：你自己的抽屉（当前作用域的变量）、一张写着"往上汇报给谁"的门牌（作用域链，指向上一层环境）、还有一块"这活儿最终谁拍板"的牌子（this）。项目干完工位拆掉，下一单再来一个。函数每调用一次就新开一个工位，调用栈其实是一摞工位的堆叠。

**变量提升**，像早上点名。正式干活前，HR 先把所有"人名"（变量和函数声明）登记进花名册——但只登记名字，人还没到岗（赋值留在原地）。所以你点名时名字在册、人却不在（值是 undefined）。`let`/`const` 的人也被登记了，但被拉进一段"隔离观察期"（暂时性死区 TDZ），观察期内去点他直接报错"这人还不能见"。

**作用域和作用域链**，像公司保密权限。你在哪间办公室写的代码，就归哪间办公室的权限圈管——不是你在哪间被叫去干活就归哪间。所以在总部（全局）写的 inner 函数，哪怕被分部（outer）叫去执行，找资料还是先翻总部的柜子。翻自己柜子没有，就顺着门牌去上一层办公室找，一层层直到总部，都没有才报错——这条"找文件的路线"就是作用域链。

### 🔍 原理下沉

JS 引擎跑代码分两步：**编译（创建）阶段** 和 **执行阶段**。编译阶段不执行代码，只做准备工作，执行上下文就在这时候搭好。

一个执行上下文里有三块（ES5 之前叫变量对象 VO / 活动对象 AO，现在规范用词法环境 LexicalEnvironment 和变量环境 VariableEnvironment，本质一回事）：
- **变量环境**：收 `var` 声明的变量和函数声明；
- **词法环境**：收 `let`/`const` 声明的变量，并带着指向外层的 `outer` 引用；
- **this**：看调用方式（前面那篇讲过了）。

提升提到哪、怎么提，分三种：
1. `var x`：声明提进变量环境，初始化成 `undefined`，赋值留原地——声明前访问是 `undefined` 不报错；
2. **函数声明** `function f(){}`：整个函数（声明+函数体）一起提，声明前就能调用；
3. `let`/`const`：也分配了内存（也"提升"了），但声明语句执行前处于 TDZ，访问直接 `ReferenceError`。

> 版本演进提醒：ES6 之前只有 `var` 和函数作用域，循环变量泄漏、`if` 里 var 外溢是家常便饭；`let`/`const` 带来块级作用域 + TDZ，把"用了没声明的变量"从静默 bug 变成明面报错，是好事。

误区必须说清：**"提升"不是真的把代码挪到顶部**。是引擎在编译阶段把声明登记进内存（执行上下文），你的源码一行没动，所谓"提升"只是个方便理解的心智模型。

### 🔁 对比学习（var vs let/const · 函数声明 vs 表达式 · 词法作用域）

```js
// 1. var：提声明 + undefined
console.log(a)        // undefined（不报错）
var a = 10

// 2. let/const：提了但 TDZ，访问报错
console.log(b)        // ReferenceError: Cannot access 'b' before initialization
let b = 20

// 3. 函数声明：整段提，声明前可调用
foo()                 // 'foo'
function foo() { console.log('foo') }

// 4. 函数表达式：本质是个变量，只提变量名
bar()                 // TypeError: bar is not a function
var bar = function () { console.log('bar') }
```

词法作用域经典题，面试老爱问：

```js
var a = 1
function outer() {
  var a = 2
  inner()             // inner 不是在 outer 里定义的
}
function inner() {
  console.log(a)      // 输出 1，不是 2
}
outer()
```

为什么是 1？`inner` 定义在全局，它的作用域链在**写代码那一刻**就锁死指向全局了。哪怕在 `outer` 里被调用，也改变不了"去哪找变量"——这就是词法作用域（静态作用域），跟调用位置无关。动态作用域的语言（比如 bash）才看调用位置，JS 不是。

顺带接一下前面闭包那篇：闭包能"攥着"外层变量不放，靠的就是这条作用域链没断。React 的 stale closure（陈旧闭包）之所以让人懵，根子也在作用域链——`useEffect` 的回调捕获的是**那次渲染**的作用域环境，不是最新值。理解了作用域链，stale closure 就不玄了。

### 💥 我踩过的坑

最丢人的是循环 + `var` + 事件绑定：给一组按钮加点击，循环里用 `var i`，结果每个按钮点出来都是最后一个 `i`。当时不懂作用域，还在那数按钮下标。后来知道 `var` 是函数作用域、循环里只有一份 `i`，换成 `let` 每行一份绑定，或包一层 IIFE 把 `i` 当参数传进去，立马好。

还有个坑是 `undefined` 和 `ReferenceError` 分不清。一度以为"变量用了没声明"都是 `undefined`，结果 `let` 的 TDZ 直接抛错，逻辑断在那。现在看到声明前的访问，我会先想"这是 var 还是 let"——var 是温柔的 undefined，let 是凶的报错。

这块我坦白：执行上下文的 VO/AO 那些老术语我能讲，但让我徒手写一遍"创建阶段 AO 长啥样"，我还得翻一下。原理懂，细节不熟。

### 🎯 面试官可能追问

- `let`/`const` 到底有没有提升？（有，分配了内存，只是 TDZ 期间不让访问，所以表现像"没提升"）
- 为什么会有 TDZ，是 bug 吗？（不是，故意的，把静默 bug 变显式报错）
- 函数声明和函数表达式的提升差别？（声明整体提，表达式只提变量名）
- 词法作用域和动态作用域区别？（JS 是词法/静态，由定义位置定，不看调用位置）
