### 事件循环：宏任务 / 微任务，以及浏览器和 Node 的差异（⭐️⭐️⭐️）

**一句话结论：** JS 是单线程，但它靠"事件循环"把异步安排得明明白白——同步代码先一口气跑完，然后**清空所有微任务**，再取**一个宏任务**跑，跑完又清空微任务……浏览器还会在宏任务之间穿插渲染。记住一句话：微任务永远插在"当前宏任务结束、下一个宏任务开始前"全清掉。

### 🍳 生活类比

把事件循环想成**银行柜台**：

- 同步代码 = 柜台前正在办的那位客人，不办完不走；
- 宏任务（`setTimeout`、IO 回调等）= 取了号在等候区排队的，到点叫号才办；
- 微任务（`Promise.then`、`queueMicrotask`）= 办完当前这位，柜员**顺手把"同一拨里冒出来的小事"全处理完**（比如"再开张发票""改个手机号"），这些小事办的时候又冒出小事，继续办，直到没事了才叫下一个号。

所以微任务赖在柜台前不走——一个宏任务结束后，所有微任务会一口气清空，才轮到下一个宏任务。这也是为什么 `setTimeout(fn, 0)` 永远跑不过 `Promise.then`：微任务插队在前。

### 🔍 原理下沉

浏览器里的硬规则（HTML 标准定义）：

1. 调用栈清空；
2. **把所有微任务跑光**（包括清空过程中新加进来的）；
3. 取**一个**宏任务跑；
4. 回到第 2 步。浏览器在两次宏任务之间还可能跑 `requestAnimationFrame`、做样式/布局/绘制。

微任务源：`Promise.then/.catch/.finally`、`queueMicrotask`、`MutationObserver`（浏览器）。
宏任务源：`setTimeout`、`setInterval`、IO 回调、`postMessage`、用户交互；浏览器里 `requestAnimationFrame` 在渲染前单独跑，不算普通宏任务队列。

`async/await` 没魔法——`await` 后面那段就是个微任务续体。函数体跑到第一个 `await` 之前是同步的，之后整段被塞进微任务队列。这点面试老挖坑。

> Node 差异提醒：Node 用 libuv，宏任务被拆成 **timers → pending → poll → check → close** 几个阶段，每个阶段跑完都会清空微任务。两个 Node 特有的：`process.nextTick` 优先级**比 Promise 微任务还高**（每次阶段切换先清它，递归用会饿死 IO）；`setImmediate` 在 check 阶段。顶层脚本里 `setTimeout(0)` 和 `setImmediate` 谁先跑**不确定**，但在 IO 回调里 `setImmediate` 一定先跑（poll 之后紧接 check 阶段）。

### 🔁 对比学习（和 Vue / React 的真实体感）

Vue 的 `nextTick` 默认就是把回调丢进微任务（Promise.then）——所以你改了响应式数据，DOM **不是立刻**变，得等本次同步代码跑完、微任务清空后才更新。理解事件循环，就不奇怪"为什么 `this.list.push` 之后立刻 `console.log(dom)` 拿不到新节点"。

React 的 `setState` 在 React 18 里默认自动批处理（一次事件里的多次 set 合并成一次更新），本质也是把"通知更新"延后到当前同步段之后——和微任务清空时机的味道一致。

### 💥 我踩过的坑

第一个是**微任务递归饿死页面**：有次写着玩 `function loop(){ queueMicrotask(loop) } loop()`，页面直接卡死，因为微任务永远清空不完，浏览器一直没机会渲染和响应点击。换成 `setTimeout(loop, 0)`（让出到宏任务）就好了——宏任务才是"喘口气"的间隙。

第二个是 **async/await 顺序题**：`await null` 之后那行以为是异步、其实要等微任务轮到才执行，和同步混着排输出顺序时栽过。现在看到 `await` 就提醒自己"后面整段是微任务"。

Node 那套阶段细节我坦白：timers/check 我能讲个大概，`process.nextTick` 的坑也知道，但让我徒手画出完整阶段流转图、或者精确说清 poll 阶段怎么让出，我还得翻文档。面试深问这块我会如实说"了解大概，细节在补"。

### 🎯 面试官可能追问

- 这段代码的输出顺序？（同步 → 所有 `.then` → `setTimeout`）——必考题，现场写一遍。
- 为什么微任务队列无限长会卡死 UI，宏任务不会？（宏任务之间浏览器能渲染/响应输入，微任务清空是"一口气"的）
- `requestAnimationFrame` 算宏任务还是微任务？（都不算，它在渲染前单独阶段，下一帧才跑）
- Node 里 `setImmediate` 和 `setTimeout(0)` 谁先？（顶层不定；IO 回调里 setImmediate 先）
