## Promise 状态机与 then 链式（⭐️⭐️⭐️）

**一句话结论：** Promise 是个状态单向锁死的容器——pending 一旦走到 fulfilled 或 rejected 就回不了头；`then` 不在原地干活，而是**返回一个新的 Promise**，值靠 `return` 往下传；这也是链式调用的根。

### 🍳 生活类比

Promise 像**外卖订单**：下单没出餐是 `pending`；出餐送达是 `fulfilled`（带份"值"回来）；关门缺货是 `rejected`（带个"原因"回来）。订单状态一旦定就改不了——餐到手了不能变回"没出餐"，黄了也不能变"成了"。这是 Promise 最让人安心的地方：它不反复横跳。

`then` 像"餐好了通知我干点啥"，而且每次 `then` 都会甩给你**一个新的订单号**（新 Promise）。你想接着干第二件事，得在新订单上再 `then`，不能在第一单上原地改。链式就是这么一节节接出来的。

### 🔍 原理下沉

**状态机**：只有 `pending / fulfilled / rejected` 三种。从 `pending` 出发只能单向到 `fulfilled` 或 `rejected`，到达即锁死。不少人以为 `resolve` 之后再 `reject` 能翻盘——不行，第二次调用直接被无视。

**then 返回新 Promise**：`then` 内部规则——它**立刻返回一个新 Promise（叫 p）**，p 刚返回时一定是 pending。你传进去的回调怎么收场，决定 p 的终态：
- 回调 `return` 一个值 → p 以这个值 fulfilled；
- 回调啥也不 `return` → p 以 `undefined` fulfilled（**这坑最多人踩**）；
- 回调 `throw` → p 以这个错误 rejected；
- 回调 `return` 另一个 Promise → p 跟着那个 Promise 的状态走。

所以链式里**值靠 return 传递，不靠副作用**。某环没 `return`，下一环拿到的就是 `undefined`。

> 版本演进：Promise 是 ES2015 才进标准，之前靠回调，嵌套出"金字塔地狱"。async/await（ES2017）是 Promise 的语法糖，把异步写得像同步——底层还是这套状态机 + 微任务，没变。

### 🔁 对比学习（回调地狱 vs Promise 链 vs async/await）

```js
// 回调地狱：三层缩进、错误散落
getUser(id, (user) => {
  getOrders(user.id, (orders) => {
    getDetail(orders[0], (d) => { /* ... */ })
  }, errHandler)
}, errHandler)

// Promise 链：纵向拍平，错误一路到 catch
getUser(id)
  .then(user => getOrders(user.id))
  .then(orders => getDetail(orders[0]))
  .catch(err => console.error(err))

// async/await：同步长相，本质还是 Promise
async function load() {
  try {
    const user = await getUser(id)
    const orders = await getOrders(user.id)
    return await getDetail(orders[0])
  } catch (err) {
    console.error(err)
  }
}
```

Vue / React 体感：Vue 的 `methods` 里 `async handleClick() { const res = await api() }` 很顺；React 函数组件 `useEffect` 不能直接 `async`（effect 得返回清理函数），得在里面包一层 `async () => {...}()`。两边拿到的都是 Promise，写法不同底层一样。

核心差异一句话：**回调是"你等我喊你"；Promise 是"我先给凭据，好了凭据自己触发后续"；async/await 是给凭据套了件同步外衣。**

### 💥 我踩过的坑

`then` 里忘了 `return`，赌下一环能拿到值，结果收到 `undefined`。现在铁律：每环要么 `return` 下一个 Promise，要么明确这环就是终点。

还有以为 `then` 同步——`Promise.resolve().then(fn)` 后面紧接一行代码，我赌 fn 先跑，结果先跑的是后面同步行。记住：**then 回调永远异步**，哪怕 Promise 早已 settled。

### 🎯 面试官可能追问

- `then` 返回什么？为什么能链式？（返回新 Promise，起始 pending）
- 链式里值怎么传？（靠 `return`，不 return 下一环收 undefined）
- 手写简易 Promise？（看状态机 + then 返回新 Promise 的理解，这块我得临场推）

## 微任务与宏任务：Promise 在事件循环里的位置（⭐️⭐️⭐️）

**一句话结论：** `then` 的回调不是同步跑的，它被塞进**微任务队列**；一轮循环里，同步代码先跑完，再**清空所有微任务**，最后才轮到一个宏任务。所以 Promise 回调永远排在 `setTimeout` 前面，哪怕定时器写 0ms。事件循环总览见 03 章，这里只抠 Promise 相关的微任务细节。

### 🍳 生活类比

还是外卖：`then` 的回调像"餐一做好，骑手**立刻**给你送（插队，本轮就到）"；`setTimeout` 像你定的"0 分钟后响的闹钟"——听着是 0，但它归宏任务管，**得等本轮所有微任务送完，下一轮才轮到它响**。所以哪怕闹钟写 0，也永远排在 Promise 后面。

### 🔍 原理下沉

几个必须钉死的点：
1. **Promise 构造器里的代码是同步的**。`new Promise(resolve => { console.log('同步') })` 会立刻打印，只有 `.then()` 的回调才进微任务。
2. **哪怕 Promise 早已 settled，`then` 回调也永远异步**。MDN 原话：调用总发生在异步时刻。所以 `Promise.resolve().then(fn)` 一定晚于当前同步代码。
3. **微任务清空是"一轮全清"**：微任务执行时新产生的微任务，会接着在本轮一次性跑完，直到队列空。
4. **`await` 后面是微任务**：`await` 前面的代码同步，`await` 之后的代码整体被包装成 `then` 回调，进微任务。

经典题，面试老爱甩：
```js
console.log(1)
setTimeout(() => console.log(2))
Promise.resolve().then(() => console.log(3))
console.log(4)
// 输出：1 4 3 2
```
解析：同步 1、4 先跑；清微任务 3；最后宏任务 2。哪怕 setTimeout 是 0，也排在微任务后。

两个 `then` 的微任务嵌套：
```js
Promise.resolve().then(() => console.log('a')).then(() => console.log('b'))
// a 然后 b：第二个 then 是第一个微任务执行时新产生的微任务，本轮接着跑
```

> 浏览器 vs Node 提醒：前端面试默认按**浏览器**事件循环答——一轮 = 清空全部微任务 + 单个宏任务。Node 基于 libuv 分 6 阶段，还有 `process.nextTick` 优先级高于 Promise 微任务，别混。

### 🔁 对比学习（微任务 vs 宏任务清单）

| 类别 | 常见成员 | 时机 |
|------|----------|------|
| 微任务 | Promise.then/catch/finally、queueMicrotask、MutationObserver、await 之后代码 | 当前宏任务结束、**本轮清空** |
| 宏任务 | setTimeout/setInterval、DOM 事件、AJAX 回调、整体 script | 下一轮循环，一次一个 |

Vue / React 里最容易撞的：组件里连续 `await` 两次接口，两次后续代码都进微任务，不会插进宏任务；但如果你在 `await` 之间写了 `setTimeout(..., 0)`，那个回调一定排在所有微任务之后。

### 💥 我踩过的坑

刚学时被那段 `1 4 3 2` 搞反过，赌 `1 2 4 3`（把 setTimeout 当最优先）。后来记住"同步 → 微任务 → 宏任务"这句话，现在能秒答。

另一个：`queueMicrotask` 和 `Promise.then` 都是微任务，我一度以为有先后——其实同属微任务队列，按入队顺序跑，没有谁天生优先（Node 的 `process.nextTick` 除外，它比 Promise 微任务还早）。

### 🎯 面试官可能追问
- 执行顺序口诀？（同步 → 清空微任务 → 一个宏任务）
- Promise 构造器里是同步还是异步？（同步；只有 then 回调异步）
- `await` 后面的代码算什么任务？（微任务）
- 微任务执行时产生新微任务，会立刻执行吗？（会，本轮清空）
